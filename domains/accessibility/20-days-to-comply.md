Read [20 minutes to the ADA and WCAG](20-minutes-to-ada-and-wcag.md) first. Each day below is one to two hours of work for the person leading the effort. If a step is already done, check it and move on. The order matters more than the day numbers: inventory before risk, and risk before policy.

## The plan

| Day | Do this |
|---|---|
| 1 | Name the person responsible for accessibility, and set the target: WCAG 2.1 or 2.2 Level AA. |
| 2 | List your digital properties: websites, apps, portals, booking and payment widgets, social media, and posted documents. |
| 3 | Pick the ten most important pages or flows: home, contact, booking, checkout, sign-in, forms, and top content. |
| 4 | Run an automated checker, such as WAVE or axe, on those pages. Save the results. |
| 5 | Tab through each key flow with only the keyboard. Note anything you can't reach or see focus on. |
| 6 | Try the key flows with a screen reader (VoiceOver or NVDA). Note what's confusing or missing. |
| 7 | Fix color contrast problems in the site's theme. |
| 8 | Add missing alt text, and mark decorative images. |
| 9 | Fix form labels and error messages. |
| 10 | Fix empty links and buttons, and set the page language. |
| 11 | Fix heading structure on templates. |
| 12 | Caption videos and add transcripts for audio. |
| 13 | List PDFs. Replace key ones with web pages or tag them properly. |
| 14 | Check third-party widgets. Ask vendors for an accessibility conformance report (VPAT) and a fix plan. |
| 15 | Publish an accessibility statement with a way to report barriers and get help. |
| 16 | Train content editors and developers. Use the [facilitator guide](../../training/facilitator-guide.md) and record it in the [training log](../../templates/training-log.csv). |
| 17 | Add accessibility checks to the publishing checklist and the development definition of done. |
| 18 | Write accessibility requirements into vendor contracts and requests for proposals. |
| 19 | Recheck the ten key pages. Record what's fixed and what remains. |
| 20 | Set the calendar: quarterly spot checks, an annual audit, and reviews before any redesign. Government entities and HHS recipients: track your 2027 or 2028 deadline. |

## After day 20

- Every quarter: spot checks of key pages with an automated tool and a keyboard.
- Every year: a fuller audit, including testing with assistive technology, and refresher training for editors.
- Before launching anything new: accessibility requirements in the design and a check before release.
- When someone reports a barrier: a response and a fix, tracked to closure.
